# Space Captains

Indirect-control space sim in the spirit of Majesty 2. You are a station administrator in a star sector. Ship captains (miners, escorts, scouts, bounty hunters) act on their own; you steer them with paid contracts (mining, explore, protect, bounty). Rich asteroid belts are more dangerous. Resources: credits (pay contractors) and typed ore (iron, titanium, crystal: for building, tooling, and to sell to the Factory, which makes the modules captains buy).

Design: docs/DESIGN.md (agreed design and stages, read it first). Reference: ../majesty/docs/MAJESTY2_MECHANICS_RESEARCH.md (fantasy original, mechanics only).

## Engine and tools
- Godot 4.7, Forward+ renderer, GDScript. Binary: /Applications/Godot.app/Contents/MacOS/Godot
- Blender 5.2. Binary: /Applications/Blender.app/Contents/MacOS/Blender
- Blender owns meshes/materials, exported as .glb to assets/models/. Godot owns scenes, lighting, gameplay. Never edit imported mesh data in Godot.
- Blender source scripts live in blender/ (headless bpy scripts, re-runnable).

## World conventions
- 1 unit = 1 m. Y is up. "Thick disc": the system has a main orbital plane (y = 0), but planets and moons orbit on inclined planes (PlanetDef inclination), asteroids come in clusters (AsteroidCluster: a 1 to 3 km clump on a slow inclined orbit, finite ore, fades when mined out; ClusterSpawner keeps 4 to 6 alive), dens sit at fixed spots at a height, and the home station rides its planet's height. Ships fly in 3D within this disc: they fly a lane over or under a cluster only when their route crosses it (AsteroidCluster.lane_altitude), miners drop to their rock's real height, and planet avoidance uses spheres. Travel legs fly cruise arcs (CruiseLeg, highway rule) and combat is 3D (AttackRun: tilted orbits, dive/climb passes, pitch aiming, fleeing dives). Structures stay level in the station's frame.
- Scale: cluster (home plus 6-9 generated systems linked by gates, see below) -> solar system (one scene each, ~50 km radius, compressed scale, star at origin) -> local area (zoomed in on a colony/belt/station). Godot float precision is fine inside one system; never put two systems in one scene.
- Planets move slowly on orbits (pausable sim time). Home station orbits a planet.
- Structures stand free near the station (no corridors); cargo shuttles fly goods from the outposts to the station's docking pads.
- Station hub radius ~40 m. Asteroids 2 to 25 m. Ships (later) 5 to 20 m.
- Camera is a tilted top-down RTS camera, zooms from ~80 m (station) to the whole system.
- Main scene is scenes/main_menu.tscn (New game / Continue / Load); the game scene is scenes/game.tscn. Saves: SaveManager autoload, scripts/save/, user://saves/.
- One system per World3D: scenes/game.tscn (root ViewManager) holds each live system as scenes/system.tscn (root SystemWorld: SolarSystem, RTSCamera, Buildings, Combat, ContractMarkers) inside its own SubViewport (own_world_3d) under its own container (SystemView for home, a SystemHost per live remote system), and the HUD, ScreenshotMode, Selection, Placement and ZonePlacement at the top, outside every system.
- Views: home is always live; a remote system is live only while viewed plus 20 s real grace (ViewManager.view / view_now, SystemHost.materialise from its RemoteSystemState, dematerialise back). Only the viewed container draws, renders, listens and gets input. SystemWorld.system_id / is_home: remote systems have no Buildings or ContractMarkers, CombatWorld has no raid/threat director, claims, zones or alarm there, ClusterSpawner is off. UI rebinds on ViewManager.view_changed (HUD.view_rebound; hud.manager stays home's, hud.local_manager() is null remote; HUD.focus(node) switches to the node's system). Save syncs live remotes into Sector first; load starts at home. Top bar system name = system menu; H returns home; --view-all (or ViewManager.debug_view_all) allows every system.
- Not-live systems are data, stepped by RemoteSim (child of ViewManager): den counters ("pending" launches built on the next visit), scrap ageing, ship dicts on generic trips (start_trip, trip_finished). Gate trips: GateTransit (Ship.jump_to / start_transit, hops + dwell): fly to the portal, run in, leave as a ShipCodec dict into Sector.transits (8 s sim), come out of the target gate (re-created if live, else stored as data); back home the brain docks. Never reparent across worlds. Captain/home/contracts are resolved by save id (SystemHost.known_refs); Captain.away_slot keeps the berth. Debug: GateTransit.debug_round_trip(tree, "Ostra Gate", dwell).
- System-side lookups are node-scoped: X.of(node) (SolarSystem, BuildingManager, CombatWorld, RTSCamera, DefenseZones, PlanetClaims, ColonyAlarm) go through SystemWorld.of(node) (the node's viewport meta; nodes outside every system get the viewed one). Group scans: SystemWorld.nodes_in(node, group). Static helpers take a node in the system (ctx: Node), never the SceneTree. Global code (autoloads, saves) asks SystemWorld.home(tree). Screen-space UI uses SystemWorld.camera_3d(self), not get_viewport().get_camera_3d().
- Generated network: autoload Sector owns a ClusterNetwork (scripts/cluster/) built from one seed per game (new seed on new game, saved under "cluster" {seed, generator_version, systems: RemoteSystemState dicts}; SystemDefs are regenerated from the seed, never saved; old saves get a fresh seed). Home is fixed (data/systems/home_system.tres); ids "home", "s1".., s1 = Ostra, s2 = Kharon (behind the home gates of those names). SystemGenerator makes each remote SystemDef from (seed, id, depth, danger, links); names come from data/cluster/name_pool.tres through one allocator, so planet/moon names are unique across the network (planet raid records key by name). A gate is named after its target ("Solace Gate" leads home) and its GateDef holds target_system + target_gate; home's gates get theirs on every new game and load. Changing what a seed generates: bump SystemGenerator.VERSION. Debug: SystemPreview.build(parent, def) shows a generated system in a throwaway SubViewport.
- Exploration (P3): Explorer Outpost (research Jump navigation) hires explorers (ExplorerShip, ExplorerBrain, ExplorerEvaluator) for ExploreContract (on a JumpGate by system id + gate name, escrowed, paid once on return). The survey data rides in the trip (trip.meta["survey"], scripts/cluster/survey.gd): Survey.plan (rings), Survey.reveal_along (the one reveal, used live by the brain and as data by Survey.step_data from RemoteSim), GateTransit out and home (CaptainBrain.takes_ship_back hands the ship to the brain at the target). Reveals go to RemoteSystemState.revealed (Sector.reveal, signal revealed); finds to Sector.discoveries (delivered on return, P4 pays). FogOfWar (child of a live remote SystemWorld) hides unrevealed 3D nodes; UI skips nodes not is_visible_in_tree() and lists via FogOfWar.is_revealed. ContractBoard.held keeps a cancelled explore contract while its explorer is out.
- Payoffs (P4): DiscoveryBounty (scripts/cluster/discovery_bounty.gd) pays delivered, unpaid Sector.discoveries once (income "Discovery", 20% finder's cut to the wallet). Derelicts: Derelict node (scripts/derelict.gd, built by SolarSystem.derelicts, fog-aware) and DerelictLoot (seeded roll per hulk, the explorer's visit live in ExplorerBrain._visit_step and as data in Survey._visit_data, loot in the survey dict, RemoteSystemState.looted via Sector.mark_looted, delivered with the survey). ClusterMap (scripts/ui/cluster_map.gd, HUD.cluster_map, M / top bar MAP; ship markers are N now). Gate raids: GateRaidSource (CombatWorld.gate_raids, home only, saved as "gate_raids", restored before the ships) with a GateRaidDen stand-in base at the home gate (not in the den group); no RNG member on it, rolls seeded from the network seed (keeps the smoke test's per-node seeding unchanged).
- SystemView renders the SubViewport at window pixel size with a 1920x1080 2D size and forwards the input nobody at the top took (camera drag/zoom); keep new 3D-world input on RTSCamera-style _unhandled_input inside the system, or at the top level next to Selection.

## Layout
- scenes/      .tscn (game: scenes/game.tscn, one system: scenes/system.tscn)
- data/systems/ SystemDef .tres, one per star system (home; the rest are generated)
- data/cluster/ name pool of the generated gate network
- scripts/     GDScript
- shaders/     .gdshader
- assets/models/{asteroids,station,gate,buildings,ships}   .glb from Blender (station addons: assets/models/station/addons, attached to the station's addon_bay_1..6 empties)
- blender/     bpy scripts that generate the .glb files

## Run
- Editor: Godot --path . -e
- Play:   Godot --path .
- Screenshot check: Godot --path . -- --screenshot=/abs/path/out.png  (renders ~90 frames, saves, quits)
- Smoke test: tools/smoke.sh [--minutes N] [--multi] [--explore] [--long]  (--multi adds view switches and a merc gate round trip; --explore runs one explore contract on Ostra Gate to the payout, fixed network seed, with the bounty and salvage lines; --long runs 40+ sim min on a fixed seed and prints the gate raids; headless new game with outposts, crews and a mining contract, seeded, ~10 sim min in a few seconds; prints credits, ships by role, raids, ore delivered, contracts, error count; exit 1 on script errors; writes no saves)
